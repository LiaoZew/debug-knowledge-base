# 调试方法论

遇到问题时的通用排查流程,避免"乱试"。

## 通用流程

1. **稳定复现** —— 先把问题变成必现,记录最小复现步骤与输入。
2. **完整信息** —— 保存完整日志 / 报错,不截断第一现场。
3. **二分定位** —— 缩小范围:注释代码、替换模块、回退版本、换环境。
4. **提出假设并验证** —— 一次只改一个变量,记录每次结果。
5. **确认根因** —— 能解释现象、能预测变化,才算找到根因。
6. **修复并验证** —— 复现原场景确认解决,检查没有引入新问题。
7. **沉淀记录** —— 用模板写一篇记录,并登记到速查表。

## 常用手段

- **看日志**:完整报错的第一行 + 调用栈 + 上下文往往指向根因。
- **对比法**:和能正常工作的环境 / 版本 / 配置逐项对比。
- **最小化**:把问题剥到最小可复现单元。
- **二分法**:对代码、配置、提交历史做二分。
- **顺藤摸瓜**:从现象沿数据流 / 调用链正向或反向追踪。

## 提问清单(卡住时自问)

- 最近改了什么?(代码 / 配置 / 环境 / 依赖)
- 它以前正常过吗?从哪一刻开始不正常?
- 报错的字面意思是什么?有没有被我忽略的关键词?
- 能构造一个最小复现吗?
- 换个环境 / 换个人会不会一样?
