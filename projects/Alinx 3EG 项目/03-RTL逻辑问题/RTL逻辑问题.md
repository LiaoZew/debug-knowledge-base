# RTL 逻辑问题(实测踩坑)

> 项目:Alinx 3EG | 语言:Verilog
> 状态:均已解决

## 3.1 按键消抖"永远没反应"

- **现象**:VIO 里按键状态一直是 0,怎么按都没变化。
- **根因**:消抖写法 `if (key_in_d2 != key_stable) cnt<=0;`,`key_stable` 上电初值 0,而按键**松开态是 1**,导致"不等"永远成立、计数器反复清零、状态卡死。
- **解决**:改为「相等才清零、不等则累加,计数满才提交」;即
  ```
  if (in != stable) begin
      if (cnt == MAX) begin stable <= in; cnt <= 0; end
      else cnt <= cnt + 1;
  end else cnt <= 0;
  ```

## 3.2 UART 接收完全无数据(RX 边沿极性写反)

- **现象**:回环收不到任何字节,纯 TX 测试却正常。
- **根因**:起始位是**下降沿**(空闲高→起始低),而代码 `wire rx_negedge = rx_d2 & ~rx_d3;` 实际检测的是**上升沿**。
- **解决**:改为下降沿 `~rx_d2 & rx_d3`(用已同步的 d2/d3)。用 TX 单向测试隔离确认方向,是定位关键。

## 3.3 纯回环连续发送丢字节

- **现象**:`0123456789` 只收回 `02468`。
- **根因**:RX 瞬时速率可超过 TX,无缓冲时收到的字节在 TX 忙时丢失。
- **解决**:收发之间加同步 FIFO,或(简单握手)确保 TX 空闲再接收。

## 3.4 UART TX 重复发送

- **根因**:`tx_valid` 与 `tx_ready` 电平握手存在一拍重叠,帧结束后 TX 在 IDLE 又看到 `tx_valid=1` 而重发。
- **解决**:TX 用 valid 上升沿触发;或配合 FIFO 让数据在每次接受后推进(不会重发同一个字节)。

## 3.5 串口发出去收不到回显(固件选择问题,非驱动问题)

- **现象**:`serial::write_str "..."` 后用 `serial::read_*` 读为空;或 JTAG/VIO 模式下发完没反应。
- **根因**:**回显取决于烧录的固件**:
  - `uart_axi`(寄存器型):外部模式**不会自动回显**——收到数据进 RX FIFO 等主机读,发送要主机写 TXDATA。故单纯串口收发不会有回显。
  - `uart_loopback`:硬件**自动回显**(收到就发回),串口侧发什么收什么。
- **解决**:
  - 要"串口发→串口收"的实时回环:烧 **`uart_loopback`** 固件。
  - 要用寄存器型 `uart_axi` 回环:跑 `sw_loopback`(软件中转),或 JTAG-AXI/VIO 手动读 `RXDATA` 再写 `TXDATA`。
- **注意**:`read_char` / `read_hex` 会消费接收缓冲;连续读两次,第二次自然为空。
